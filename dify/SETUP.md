# Dify Cloud 配置

## 1. 配置 DeepSeek 官方模型

1. 登录 Dify Cloud，进入 **Plugins / 插件市场**。
2. 安装官方 **DeepSeek / 深度求索** 模型供应商。
3. 在 **Settings → Model Provider → DeepSeek** 中填写 DeepSeek 官方 API Key。
4. API Base URL 使用官方地址 `https://api.deepseek.com`，模型选择 `deepseek-v4-flash`。

> API Key 只保存在 Dify 工作区凭据中，不要写入 DSL、GitHub 或环境变量示例。

## 2. 导入 Chatflow

在 Dify Studio 选择 **Import DSL file**，导入 `dify/nearby-go-chatflow.yml`。

DSL 已按当前 Dify `0.7.0` 导出结构整理。导入后检查以下十三个节点：

1. 开始
2. 需求分流
3. 提取推荐条件
4. 合并长期记忆
5. 保存长期记忆
6. 标准化请求
7. 高德附近推荐
8. 结果可信度审计
9. 生成地图卡片
10. 生成推荐说明
11. 回复
12. 日常问答
13. 日常问答回复

增强版 Chatflow 会额外理解同行人、饮食要求、可达性、氛围、避雷项、决策偏好和回答模式，并自动在“快速选择、候选对比、单日路线、多日攻略”之间切换。结果可信度审计节点会处理无效 HTTP/JSON、空结果、定位回退和候选文本与避雷项的字面冲突；这些检查不会替代商家对过敏原、清真、无障碍或宠物友好等条件的人工确认。

Chatflow 同时包含两层记忆：提取节点读取最近 8 轮、生成节点读取最近 6 轮作为短期上下文；`user_profile` 会话变量保存用户明确授权的长期偏好。长期画像只在用户说“记住/以后默认”等明确授权语句时更新，并过滤疑似手机号、精确坐标、密钥和口令；用户可以说“忘记辣”“清空长期偏好”。该画像属于会话级记忆：前端保存 `conversation_id` 后可跨刷新继续使用，但不会自动跨设备或进入新对话。

如果模型节点显示未配置，在“需求分流”、“提取推荐条件”、“生成推荐说明”和“日常问答”节点中重新选择 `DeepSeek / deepseek-v4-flash`。

## 3. 语音输入与朗读

DSL 已移除 Dify 的 `speech_to_text`，并默认关闭 `text_to_speech`。这是因为 DeepSeek/OpenAI-compatible 文本模型不是 Dify 的默认语音模型；在工作区未配置 TTS 时开启自动朗读，会使整个 Chatflow 在运行前因 `Default model not found for tts` 失败。

当前版本 H5 已彻底移除语音输入与朗读功能，后端 `/api/audio-to-text` 端点也已删除，无需在 Dify 配置任何语音模型。

## 4. 配置 Chatflow 环境变量

DSL 携带两个环境变量的定义，其中公网后端地址使用项目默认值，内部 Token 保持为空。导入完成后，在 Dify Cloud 的 Chatflow 环境变量面板中检查并填写：

- `BACKEND_BASE_URL`：本项目部署后的公网 HTTPS 地址，不要以 `/` 结尾。
- `INTERNAL_API_TOKEN`：与服务器 `.env` 中同名变量完全一致。

不得将真实 Token 写入仓库。重新导出 DSL 后，提交前必须确认 `INTERNAL_API_TOKEN` 的 `value` 为空；`BACKEND_BASE_URL` 可以保留公开的 HTTPS 地址。

Dify Cloud 无法访问 `localhost`，因此测试“高德附近推荐”节点前，后端必须先部署到公网 HTTPS 地址。

## 5. 发布并取得应用 Key

1. 点击 **Publish**。
2. 打开 **Access API / 访问 API**。
3. 创建应用 API Key。
4. 把 Key 填入服务器 `.env` 的 `DIFY_API_KEY`，不要写进 H5 JavaScript。

H5 经后端调用：

```text
POST https://api.dify.ai/v1/chat-messages
```

输入变量由后端自动传递：`longitude`、`latitude`、`coordinate_system`、`location_accuracy`、`location_name` 和 `fallback_location_name`。`location_name` 是起点可读名称：用户在 H5 手动选点时为地点名，浏览器定位时由后端调用高德逆地理编码自动解析；生成推荐说明的节点会用它描述当前位置。

## 6. 联调

依次验证：

1. `GET /api/health` 三项配置均为 `true`。
2. 在 Dify 调试页手动填清华默认坐标 `116.3260, 40.0030`，运行 Chatflow。
3. 打开 H5，允许定位，询问“推荐附近人均 60 的晚餐”。
4. 拒绝定位再次测试，应回退到清华大学默认位置。
5. 点击答案中的“打开高德导航”。
6. 询问“帮我安排一个吃饭加游玩的三小时路线”，确认接口数据同时包含餐饮和游玩地点，且第二段从餐饮地点出发。
7. 确认三小时攻略中的“交通＋停留＋机动”合计约 180 分钟，而不是只展示几分钟步行。
8. 询问“安排三天两夜的附近吃喝游玩攻略”，确认按天输出、每天都有明确时间预算，并同时包含餐饮和游玩地点。
9. 询问“带老人步行 10 分钟内找安静晚餐，不要太辣”，确认半径约为 800 米，回答提示老人/少走路/避辣等条件仍需向场所核实。
10. 在 Dify 调试页清空经纬度，确认工作流使用清华大学默认位置且在回答开头明确告知。
11. 临时把后端地址改成不可用地址，确认回答只提示数据服务不可用，不会根据错误正文编造推荐。
12. 连续对话询问“推荐人均 80 的安静晚餐”→“还是上次那样，但改成咖啡”，确认短期记忆只承接明确省略的条件。
13. 说“记住我长期喜欢安静、少走路”，刷新页面后再次推荐，确认画像继续生效且回答确认已记住。
14. 说“忘记少走路”，确认只删除指定项；再说“清空长期偏好”，确认画像所有列表为空。
15. 普通询问“今天预算 60”，确认不会自动写入长期画像；尝试要求记住手机号、精确坐标或 Token，确认合并节点拒绝保存。
16. 询问“什么是动量守恒”，确认进入“日常问答”分支，不调用高德也不提及定位。
17. 询问“附近人均 80 的晚餐”，确认回答末尾显示高德地图、候选标记和路线摘要。
18. 在 H5 点击麦克风录制一句话，确认文字回填到输入框；发送后确认可朗读回答，并可使用顶部开关静音。

前端保留高德官方 HTTPS URI API 导航跳转，同时通过本项目后端的签名代理显示高德静态地图。浏览器不会获得 Web 服务 Key，也不需要新增 JS API Key/安全密钥。微信等限制第三方 App 唤起的内置浏览器会显示“在浏览器打开”的提示。

生产前请为 `/api/chat` 增加网关限流，并把高德/Dify 调用日志接入监控。
